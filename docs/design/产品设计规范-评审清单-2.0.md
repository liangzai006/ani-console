# 产品设计规范 · 评审清单 2.0

> **🔒 冻结（2026-06-25）**：禁止修改正文。见 [DESIGN-SPEC-FREEZE.md](./DESIGN-SPEC-FREEZE.md)。

> 用于设计评审、设计交付、前端联调、QA 走查与上线前 UI 检查。  
> 评审基准：**ANI 产品设计规范 2.0** + **Arco Design React 唯一指定**。

## 1. 使用场景


| 阶段    | 参与者        | 输出                     |
| ----- | ---------- | ---------------------- |
| 设计评审  | 产品、设计、前端代表 | 通过 / 修改 / 驳回           |
| 设计交付  | 设计师 → 前端   | 标注完整的 Figma / 原型 + 组件表 |

| 上线前   | 全员         | 快速版清单（§18）             |


---

## 2. 评审维度总览

每个页面至少检查：

1. 任务清晰度
2. 布局与页面模板
3. Arco 组件与 Token
4. 状态完整性（loading / empty / error）
5. 表单与反馈
6. 可访问性
7. 响应式（桌面优先）
8. 文案与术语
9. 跨页面一致性

---

## 3. 任务清晰度

- [ ] 3 秒内能理解页面主任务  
- [ ] 页面标题具体（含对象域，如「模型管理」）  
- [ ] 主操作唯一且使用 Primary 层级  
- [ ] 次操作 visually 退后（default / outline / text）  
- [ ] 空态或首屏引导告诉用户下一步  

---

## 4. 布局与页面模板

- [ ] 页面落在六种标准模板之一（概览 / 列表 / 详情 / 表格+检查器 / 表单 / 审计）  
- [ ] 使用标准 Page Header + Content Body 结构  
- [ ] 摘要区、详情区、操作区职责分离  
- [ ] 间距符合 4px 节奏（16 / 20 / 24 为主）  
- [ ] 无 gratuitous 装饰动画或无关插图  
- [ ] 辅助面板（筛选、检查器、AI）确实服务主任务  
- [ ] Console/BOSS 壳层符合 Layout + Header + Menu 规范  
- [ ] 首屏是否只有一个明确视觉重心  
- [ ] 是否避免满屏卡片化与多层嵌套容器  

---

## 5. Arco 组件合规

- [ ] 未出现 TDesign / Ant Design / MUI / Element 等非 Arco 组件  
- [ ] 图标来自 `@arco-design/web-react/icon`  
- [ ] 图表使用 ECharts，色板对齐 Token  
- [ ] 列表页使用 `Table`，非用 div 模拟表格  
- [ ] 确认/删除使用 `Modal`，非浏览器 `alert`  
- [ ] 浮层任务使用 `Drawer` 而非 oversized `Modal`  
- [ ] Tailwind 仅用于布局 utilities，未用 Tailwind 仿造 Arco 组件或色板（详见 [样式与 Tailwind 边界 2.0](./产品设计规范-样式与Tailwind边界-2.0.md)）

---

## 6. Token 与主题

- [ ] 设计标注使用 Arco Token 或主题变量名，非孤立 hex  
- [ ] 主文本 / 次级文本 / 边框 / 状态色语义正确  
- [ ] 状态色未滥用为大面积装饰  
- [ ] Light 主题完整可用（P0）  
- [ ] 若交付 dark：两套主题下边框、次级文本、状态色均可区分（P1）  
- [ ] 品牌色顶栏与内容区对比度足够（WCAG AA 建议）  
- [ ] 同一屏是否把颜色种类控制在必要范围内  

---

## 7. 按钮与操作

- [ ] 每个操作组仅一个 `type="primary"`  
- [ ] 危险操作使用 `status="danger"` + `Modal` 确认  
- [ ] 按钮文案为明确动词  
- [ ] 图标按钮有可见 tooltip 或 aria 名称  
- [ ] loading / disabled 态已设计且可识别  
- [ ] `Dropdown` 内不放「创建」类主操作  
- [ ] 行内操作是否足够克制，没有把每行做成按钮墙  

---

## 8. 表单

- [ ] 每个字段有 Label（非 placeholder 代替）  
- [ ] 必填 / 选填标识清晰  
- [ ] Helper text 简洁有效  
- [ ] 错误提示在字段附近，使用 `--color-danger-6`  
- [ ] 保存逻辑明确（手动提交 vs 自动保存）  
- [ ] 风险操作与保存按钮分离  

---

## 9. 表格与列表

- [ ] Table / List 选型恰当  
- [ ] 表头简洁可扫读  
- [ ] **loading、empty、error 三态均已设计**  
- [ ] 行 hover / 选中 / 可点击态可区分  
- [ ] 行内按钮不与整行 click 冲突  
- [ ] `Pagination` 位置稳定  
- [ ] 状态 `Tag` 与全站枚举一致  

---

## 10. 卡片、标签与提示

- [ ] Card 有意识分组，非全页卡片堆砌  
- [ ] Badge / Tag 表达状态，非装饰  
- [ ] 不仅靠颜色表达状态（配合图标/文案）  
- [ ] `Alert` 说明现状 + 建议下一步  
- [ ] warning 与 error/destructive 语义区分清楚  
- [ ] 是否优先使用大容器分组，而不是把每块都做成独立小卡片  
- [ ] 状态标签是否足够轻量，没有厚重彩底和过度强调  

---

## 11. 弹窗、抽屉与菜单

- [ ] Modal / Drawer 容器选择合理  
- [ ] 弹窗流程短、聚焦  
- [ ] 焦点与 Esc 关闭行为可预期（Arco 默认）  
- [ ] 菜单仅承载次级操作  
- [ ] 菜单内危险项有视觉标记  
- [ ] 是否用 Drawer 承接了更适合低打扰展示的次级内容  

---

## 12. 空态、加载态、错误态

- [ ] Empty 说明原因 + 引导操作（如「创建第一个知识库」）  
- [ ] Loading 不导致布局跳动（Skeleton 优先）  
- [ ] Error 有可操作路径（重试、刷新、查看日志）  
- [ ] 页面级错误与字段级错误分层  

---

## 13. 可访问性

- [ ] 核心流程可键盘完成  
- [ ] Tab 顺序合理  
- [ ] focus-visible 未被设计稿移除  
- [ ] 表单控件有关联 label  
- [ ] 图标按钮已命名  
- [ ] 表格结构语义正确（设计稿标注 thead/tbody 意图）  
- [ ] 动态更新有文案或 aria 提示（如加载完成）  

---

## 14. 响应式

- [ ] 1280px 基准宽度布局完整  
- [ ] 1024px 下检查器 / 侧栏有降级方案（Drawer）  
- [ ] 表格可横滚，操作列不丢失  
- [ ] 长文案截断有 tooltip 或展开  
- [ ] 触控目标不小于 32px（行内按钮）  

---

## 15. 文案与术语

- [ ] 标签短、准、可执行  
- [ ] 空态 / 错误文案独立可读  
- [ ] 术语与 `console-modules` / OpenAPI 一致  
- [ ] 避免单独使用「继续」「提交」「更多」  
- [ ] 英文文案更长时不破坏布局（P1）  

---

## 16. 跨页面一致性

- [ ] 视觉属于同一产品（Console 或 BOSS，不混壳）  
- [ ] 复用 PageHeader、StatusTag、ResourceTable 等共享模式  
- [ ] 按钮层级、间距、Tag 语义与已有页面一致  
- [ ] 未引入未经评审的新页面模式  

---

## 17. 设计交付物检查

设计师提交开发前，确认已附：

- [ ] 页面模板类型说明  
- [ ] Arco 组件标注表  
- [ ] Token 标注或引用规范章节  
- [ ] 三态稿（列表/表单页）  
- [ ] 危险操作确认 Modal 稿  
- [ ] 与模块 PRD / OpenAPI 字段对照（如有新增字段）  
- [ ] 高级感检查结论（是否存在卡片滥用、颜色过满、按钮层级混乱）  

---

## 17.5 Console 工程实现检查（前端）

实现与联调时，除视觉规范外须符合 `frontends/console/CONVENTIONS.md`：

- [ ] 页面组件与 `createFileRoute` 在 **同一路由文件**（`src/routes/`），无 `src/pages/` 拆分  
- [ ] 跨页复用 UI 在 `src/components/`，单页逻辑不在 components 中堆积  
- [ ] API 调用经 `coreApi` + 生成类型，无手写 URL  
- [ ] 新阶段完成后更新 `docs/CONSOLE-SPRINT-PHASES.md`  

---

## 18. 上线前快速版（5 分钟）

时间有限时至少核对：

- [ ] 主任务明显  
- [ ] 主操作唯一 Primary  
- [ ] 使用 Arco 组件，无平行 UI 库  
- [ ] Token 无散落 hex  
- [ ] loading / empty / error 存在  
- [ ] 危险操作有 Modal  
- [ ] 图标按钮有名称  
- [ ] 1280px 与 1024px 可用  
- [ ] 首屏没有明显卡片堆砌或颜色噪音  

---

## 19. 评审输出模板

### 通过项

- 列出已符合规范的方面

- 必须修改才能进入开发或上线

## 20. 常见驳回原因（2.0 新增）


| 问题                                 | 正确做法                    |
| ---------------------------------- | ----------------------- |
| 稿中出现 TDesign / Ant Design Table 样式 | 改用 Arco `Table` 截图或组件标注 |
| 主色每页不同 hex                         | 统一 `--color-primary-6`  |
| 删除仅 Toast 无确认                      | 增加 `Modal` + danger 操作  |
| 列表无 empty 态                        | 补 `Empty` + 创建引导        |
| 实现说明写「用 Tailwind 调 spacing」        | 改用 Arco 间距与 Layout      |
| 状态 Tag 颜色与别页不一致                    | 对照 StatusTag 映射表        |
| 首屏堆满摘要卡、提示条和筛选器                    | 收敛成一个主重心，其他信息后置         |
| 每个区块都做独立小卡片                        | 改成大容器分区，减少拼贴感           |
