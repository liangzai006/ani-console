# ANI Console UI 开发约定

本文档是 Console UI 实现细则的唯一维护位置。目标是优先复用成熟组件，以最少的自定义代码完成一致、可维护的界面；目录、命名和路由适配遵循 [工程约定](./ENGINEERING-CONVENTIONS.md)。

## 实现顺序

新增或调整 UI 前，先检索 `src/components/` 和同类页面，已有实现应优先复用或扩展，不复制为页面私有版本。

按以下顺序实现，只有前一级无法满足需求时才进入下一级：

1. 使用 Arco Design React 组件、组件 props、组件组合及已有共享组件。
2. Arco 能力满足但外观不符时，优先通过 Arco Token、主题配置以及组件公开的 `className` 或 `style` 接口做局部调整。
3. Arco 无法提供所需能力时，使用 TailwindCSS 完成布局、尺寸和间距，并封装为对应领域组件；跨页面、跨领域复用的能力封装为 `common` 组件。
4. 仅当 TailwindCSS 无法表达复杂选择器、伪状态或第三方组件内部样式覆写时，才新增组件私有 CSS/LESS 文件。变更说明中须简短说明前三级方案不能满足的原因。

## 组件与样式边界

- UI 组件使用 `@arco-design/web-react`，图标使用 `@arco-design/web-react/icon`。
- 不引入与 Arco 平行的组件库，不自行仿造 Arco 已提供的 Button、Table、Form、Modal 等基础组件。
- 颜色与状态语义使用 Arco Token；TailwindCSS 不使用独立色板替代 Token。
- TailwindCSS 主要负责布局、尺寸和间距，不开启会覆盖 Arco 基础样式的 preflight。
- 合并动态、条件或由组件外部传入的 `className` 时统一使用 `clsx`；不得使用数组过滤后 `join`、字符串拼接或模板字符串手工组合类名。
- 不复制 Arco 源码进行样式修改。局部覆写应限制在组件自身作用域，避免影响其他页面。
- 页面 Layout、菜单、导航和壳层默认不调整，只有用户明确要求时才修改。

## 页面与组件组织

- 新建页面先参考同类型已有页面；列表、详情和表单沿用已有布局与交互模式，不创建平行页面模板。
- 页面级查询、状态、导航和组件组合放在对应页面组件中，可独立识别的复杂展示或交互区域继续拆为领域组件；路由入口职责与适配规则遵循 [工程约定](./ENGINEERING-CONVENTIONS.md)。
- 服务端状态使用 TanStack Query，跨组件客户端状态使用 Zustand，组件局部 UI 状态使用 React 状态。
- 详情页中每个包含表格、布局块、条件分支、独立请求或交互流程的活动 Tab 内容必须拆为领域组件；已经直接引用现有业务组件的 Tab 不增加薄包装。被整段注释、等待接口开放的内容保持原状，不提前创建占位组件。
- 详情页 Tab 内容组件按实际业务功能命名，不使用 `Tab`、`Panel` 等容器后缀；目录、导出名及页面级组件的 `Page` 后缀遵循 [工程约定](./ENGINEERING-CONVENTIONS.md)。固定占位文案、空状态说明等由组件内部维护，不为其增加无复用价值的 props。
- 仅供某个 Tab 使用且不与详情页其他区域共享的查询、mutation、弹窗、确认框、局部状态和事件处理必须下放到该内容组件；详情页只保留跨 Tab 共享的数据与状态、顶层导航以及确需统一编排的操作，并通过明确 props 传递共享输入和回调。
- 详情页头部的资源级操作必须统一收纳在“更多操作”三点下拉菜单中，不在标题区平铺按钮或拆分主次操作；触发按钮使用竖向三点图标，并提供 `aria-label` 和 `title="更多操作"`。仅作用于某个 Tab 局部内容的操作保留在对应内容组件内，不提升到详情页头部。
- 包含动态列表、异步选项、字段联动或复杂校验的表单项，必须抽为可复用领域组件。
- 新建或改造的业务弹窗必须抽为以具体操作命名的独立领域组件，其 `Modal` 后缀、目录和导出名遵循 [工程约定](./ENGINEERING-CONVENTIONS.md)；页面、详情页和 Tab 内容组件不得内联承担完整弹窗 JSX。仅包含简短说明且没有表单、远程请求或独立状态的一次性确认可以直接使用 `Modal.confirm`。
- 弹窗的打开状态由调用方持有，并通过条件渲染挂载或卸载弹窗组件；弹窗组件内部的 Arco `Modal` 固定为可见，不得再接收或转发 `visible` prop。关闭后需要保留的状态必须有明确业务理由，不以常驻隐藏弹窗作为默认实现。
- 仅供弹窗使用的表单实例、字段校验、查询、mutation、pending 状态和事件处理必须收敛在弹窗组件内部；对外 props 只保留必要的业务输入、`onCancel` 和成功回调，不得绑定具体路由。固定标题、说明、按钮文案及空状态由组件内部维护，不增加无复用价值的展示型 props。
- 创建、部署等表单默认使用单页表单；只有用户明确指定分步流程时才使用 Steps/Wizard。
- 具体目录和组件文件结构遵循 [工程约定](./ENGINEERING-CONVENTIONS.md)。

## 用户反馈与请求状态

- 业务代码不得直接调用 Arco `Message.*` 或 `Notification.*`；即时轻反馈统一使用 `src/lib/feedback.ts` 的 `showMessage`，查询、非表单操作和后台任务反馈统一通过 TanStack Query meta 或反馈模块声明。统一反馈模块只负责 Message、Notification 的展示与关闭。
- 所有用户可见查询必须配置 `meta.errorNotification`；确需静默的查询必须在查询定义旁注明原因。查询成功时由全局 `QueryCache` 关闭同 ID 的旧错误通知。
- 所有 mutation 必须配置 `meta.feedback`。表单提交使用 `channel: "message"`，非表单操作及后台任务使用 `channel: "notification"`；组件回调只保留缓存失效、关闭弹窗、导航等业务副作用。
- Query 与 mutation 的反馈 ID 必须使用短且页面无关的业务语义名称；同一数据源或同一操作在不同入口复用同一 ID，禁止包含文件路径、组件名或页面名。需要关联资源 ID 等动态维度时统一使用 `src/lib/id.ts` 的 `withId`；查询键等需要稳定作用域标识的场景复用同一工具。
- 禁止新增远程错误的组件内 `Alert`、`Result`、错误文本或错误专用重试占位。列表、表格查询失败且无数据时直接使用组件既有空占位，不得为错误状态新增 `loadFailed`、`failed`、空白壳层或条件包装；后台刷新失败且已有缓存数据时继续展示缓存数据。
- 表单必须同时保留 `Form.Item` 字段级校验和提交级 Message；直接调用 `form.validate()` 时必须经过统一校验入口，避免漏提示或重复提示。接口提交成功或失败也使用 Message。
- 非表单操作和后台任务使用 Notification；loading 通知常驻，并通过同一稳定 ID 更新为成功或失败。复制、无变化等即时轻反馈使用 Message。
- 资源自身业务状态（包括名为 `error` 或 `failed` 的状态值）及静态说明、风险提示类 Alert 不属于远程请求错误提示，不得机械删除。

## 组件拆分判断

文件行数用于提示职责是否过多，不作为机械拆分目标：

- 路由文件尽量控制在 150–300 行，只负责路由参数、页面状态编排和组件组合。
- 业务组件通常控制在 80–200 行；超过 250 行时，应检查是否承担了多个职责。
- Hook 或状态逻辑超过 80–120 行，或包含多组相互独立的操作流程时，应考虑抽取。
- 单文件页面超过 500 行时通常应拆分，除非内容高度线性且拆分后无法形成清晰、可复用的职责边界。

满足以下任一条件时，优先拆为具有明确业务名称的领域组件或 Hook：

- 区域拥有独立标题、表格、弹窗或交互边界。
- 区域拥有独立状态和操作流程。
- 可以用明确业务名称描述，例如“设备表”或“租户分配台账”。
- 区域需要单独维护、验证或复用。
- 修改一个区域时，经常需要在大文件中来回查找相关代码。
- `useState`、事件处理函数或表格 `columns` 明显成组出现。

以下情况不应仅为缩短文件而拆分：

- 只有十几行、没有独立业务语义的 JSX。
- 组件只转发一层 props，未隔离状态、行为或展示复杂度。
- 拆分后需要传递大量零散参数，反而增加调用关系和理解成本。

## 交互底线

- 空值或无内容的文本占位统一使用半角连字符 `-`，不得使用破折号 `—`。
- 危险操作必须二次确认，并明确操作对象或影响。
- 表单控件必须有可识别的标签，校验错误显示在相关字段附近。
- 保留 Arco 默认的键盘操作和焦点样式；纯图标操作提供可访问名称或可见提示。
- 长文本、资源 ID 和表格内容不得破坏布局；截断时提供查看完整内容的方式。
- 表格列仅直接展示数据字段时优先使用 `dataIndex`，嵌套字段使用其支持的路径写法，空值差异通过列级 `placeholder` 表达；仅格式化、组合、条件展示或交互内容使用 `render`。表格长文本统一使用列级 `ellipsis: true`，不得在单元格 `render` 中手写 `truncate` 或仅为溢出提示包装 Tooltip。
- 以桌面端为主要使用场景；常见桌面宽度下页面应可操作，表格内容过宽时允许横向滚动并保留关键操作。
