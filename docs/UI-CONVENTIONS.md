# ANI Console UI 开发约定

本文档是 Console UI 实现的唯一约定。目标是优先复用成熟组件，以最少的自定义代码完成一致、可维护的界面。

## 实现顺序

新增或调整 UI 前，先检索 `src/components/` 和同类页面，已有实现应优先复用或扩展，不复制为页面私有版本。

按以下顺序实现，只有前一级无法满足需求时才进入下一级：

1. 使用 Arco Design React 组件、组件 props、组件组合及已有共享组件。
2. Arco 能力满足但外观不符时，优先通过 Arco Token、主题配置以及组件公开的 `className` 或 `style` 接口做局部调整。
3. Arco 无法提供所需能力时，使用 TailwindCSS 完成布局、尺寸和间距，并封装为对应领域组件；跨页面、跨领域复用的能力封装为 `common` 组件。
4. 仅当 TailwindCSS 无法表达复杂选择器、伪状态或第三方组件内部样式覆写时，才新增组件私有 CSS/LESS 文件。变更说明中须简短说明前三级方案不能满足的原因。

## 组件与样式边界

- UI 组件使用 `@arco-design/web-react`，图标使用 `@arco-design/web-react/icon`。
- 不引入与 Arco 平行的组件库，不自行仿造 Arco 已提供的 Button、Table、Form、Modal 等基础组件。
- 颜色与状态语义使用 Arco Token；TailwindCSS 不使用独立色板替代 Token。
- TailwindCSS 主要负责布局、尺寸和间距，不开启会覆盖 Arco 基础样式的 preflight。
- 不复制 Arco 源码进行样式修改。局部覆写应限制在组件自身作用域，避免影响其他页面。
- 页面 Layout、菜单、导航和壳层默认不调整，只有用户明确要求时才修改。

## 页面与组件组织

- 新建页面先参考同类型已有页面；列表、详情和表单沿用已有布局与交互模式，不创建平行页面模板。
- 路由页面负责页面级查询、状态编排、导航和组件组合。可独立识别的复杂展示或交互区域拆为领域组件。
- 资源创建模态框，以及包含动态列表、异步选项、字段联动或复杂校验的表单项，必须抽为可复用领域组件。
- 创建、部署等表单默认使用单页表单；只有用户明确指定分步流程时才使用 Steps/Wizard。
- 具体目录和组件文件结构遵循 [工程约定](./CONVENTIONS.md)。

## 交互底线

- 数据列表覆盖 loading、empty 和 error 状态；错误状态提供可理解的原因或可执行的恢复方式。
- 危险操作必须二次确认，并明确操作对象或影响。
- 表单控件必须有可识别的标签，校验错误显示在相关字段附近。
- 保留 Arco 默认的键盘操作和焦点样式；纯图标操作提供可访问名称或可见提示。
- 长文本、资源 ID 和表格内容不得破坏布局；截断时提供查看完整内容的方式。
- 以桌面端为主要使用场景；常见桌面宽度下页面应可操作，表格内容过宽时允许横向滚动并保留关键操作。
